## Context

Length budgets (#167) are prose only. The one hook today is `engrenage agents claude hook edit` (`bin/engrenage/agents/claude/hook/edit.ts`, `src/agents/utils/formatEditedFile.ts`), synced into `.claude/settings.json` by `syncEditHook` as a `PostToolUse` entry. Code waits for #137 so it lands in its final domain.

Decided: budgets measured by hooks, warn by default, deny opt-in; code in `tools/agents/claude` (`operations/`, `config/`).

## Prerequisites

- #139, #141 and #143 are closed (domain layout, roles, registry).
- #167 is closed (budget values).

## Steps

1. Agents config section: per-kind budgets (task, block, plan, comment, backlog entry, debt entry) defaulting to D7's values, and a `warn | deny` mode, declared with the declaration helper.
2. Edit hook: after formatting, measure each entry of an edited `.ai/backlog/*.md` or `.ai/debt.md` and warn on those over budget.
3. New `engrenage agents claude hook github` command for a `Bash` hook matching `gh issue create|edit|comment`: measure the body (see **Questions**), classify it (plan, block, task by title prefix; comment), warn, or deny in deny mode.
4. Sync both hooks into `.claude/settings.json`, generalizing `syncEditHook` to any event and matcher.
5. Mirror both for Codex where its hooks allow (`createCodexHooksStep`).

## Tests

- A backlog entry over budget gets a warning; one within budget gets none.
- `gh issue create --body-file -` with an oversized body: warned in warn mode, blocked in deny mode.

## Done when

Both hooks are synced here and warn on oversized writes.

## Questions

- How does the GitHub hook read the body? The command passes it on stdin (heredoc inside `tool_input.command`). Candidates: `PreToolUse`, parsing the heredoc out of the command (can block, fragile parsing); `PostToolUse`, fetching the written issue or comment through `gh` (exact, cannot block, one network call). Recommended: `PreToolUse` measuring the heredoc, falling back to the whole command's length.
- Does Codex expose a shell pre-tool hook? To verify before step 5.
