# #153 config: global settings, presets, traits and tool option placement

## Context

One configuration mixes global settings (`build`, `cache`, `debug`, `define`, `presets`), environments and tool sections; ESLint, tsdown, Vite and Vitest options live in their definers; Prettier has none. `presets` is a list with one value, `library`, checked by hand at six `includes(presets, "library")` sites and by `@debt`-marked reads (#155, #159, #162).

## Steps

1. Reshape the sections, moving each key to its owning domain's declaration:
   - global settings: root, debug, cache, module type, Node and TypeScript versions;
   - `define` becomes an environment sub-config, `build` the section of `project/build`, imports and exports the package-layout sub-config of each environment;
   - general project and build options, and options valid for every engine of a kind, stay in `engrenage.config.ts`, as do tool sections without a config file (git, GitHub, VS Code, agents) and options a command reads; options of one tool move to its config file through `define<Tool>Config`.
2. Add `project/formatting`, declared public, with the `formatting` section (formatter-agnostic options: print width, quotes) and `definePrettierConfig`; move Prettier plugins and overrides to `prettier.config.ts`, read only when Prettier runs.
3. Replace `presets` with `preset`, at most one base preset bundling traits, and add `traits: { enable, disable }` (known keys, type-safe, like `roles`); explicit options override both; no environment-level presets. `project/presets` owns composition and derivation; resolvers and computed defaults read traits from context. First traits:
   - **owned directories**: directories a host owns, where no environment default lands;
   - **published**: from `library`; drives §Library versus app.
   Replace the six `includes` checks and the `@debt`-marked `library` reads with trait reads.
4. Rebuild the `engrenage init` answers on the same state: base defaults, then the preset's traits, then explicit input; pnpm stays the default package manager.
5. Migrate `engrenage.config.ts` and add one breaking changeset describing every moved key.

## Tests

- `library` resolves to `published`; a project without it gets no dist mode and no tests dist tsconfig.
- `preset: "library"` with `traits: { disable: ["published"] }` gets no dist mode.
- A host preset declaring `tests/` as owned keeps the tests environment default out of it.
- Prettier plugins declared in `prettier.config.ts` apply when formatting, without being read by `engrenage sync`'s configuration.
