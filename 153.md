# #153 config: global settings, presets, traits and tool option placement

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, under #144. Read the plan, its **Config pipeline**, **Presets and traits** and **Library versus app** sections, before starting.

## Context

- Today one configuration mixes global settings (`build`, `cache`, `debug`, `define`, `presets`), environments (`src`, `tests`, `scripts`, `bin`, `data`, `tooling`) and tool sections (`agents`, `git`, `github`, `prettier`, `typescript`, `vscode`); ESLint, tsdown, Vite and Vitest options live in their definers.
- Presets are one root list with a single value, `library`, whose effects are scattered: modules check `includes(presets, "library")` by hand at six sites, and #155 and #159 read the preset with `@debt` markers.
- Prettier has no definer: its section lives in `engrenage.config.ts`.

Decided:

- **Global settings**: root, debug, cache, module type, Node and TypeScript versions. `define` becomes an environment sub-config, `build` the `build` contract's section (`project/build`), imports and exports the package-layout sub-config of each environment.
- **Option placement**: general project and build configuration, and options valid for every engine of a kind, live in `engrenage.config.ts`; options of one tool live in its config file through `define<Tool>Config`; tools without a config file (git, GitHub, VS Code, agents) keep their section in `engrenage.config.ts`; options a command reads stay in `engrenage.config.ts`.
- **Prettier**: formatter-agnostic options (print width, quotes) form the `formatting` section of a new `project/formatting` domain; Prettier plugins and overrides move to `prettier.config.ts` through a new `definePrettierConfig`, read by the Prettier code only when Prettier runs.
- **One preset, adjustable traits**: `preset` takes at most one base preset, which bundles sensible traits; `traits: { enable, disable }` (known keys, type-safe, like `roles`) adjusts them afterwards; explicit options override both. Three layers of specificity, so most projects need almost no configuration. The `presets` list and environment-level presets disappear.
- **Traits**: presets resolve into traits; resolvers and computed defaults read traits from context, never preset names. `project/presets` owns composition and derivation. First traits:
  - **owned directories**: directories a host owns; no environment default lands there;
  - **published**: resolved from `library`; drives dist testing, `#data`, data access and the `tooling` import rule (plan, **Library versus app**).
- Projects without `published` get no dist mode and no tests dist tsconfig.
- `engrenage init` builds its answers on the same declarative state: base defaults, then the preset's traits, then explicit input.
- One breaking release, with a changeset describing the migration of every moved key.

## Prerequisites

- #143 is closed.

## Steps

1. Reshape the sections as decided, moving each key to its owning domain's declaration.
2. Add `project/formatting` with the `formatting` section and `definePrettierConfig`; move the Prettier-specific options there.
3. Replace `presets` with `preset` and add `traits`; implement trait resolution in `project/presets`; replace the six `includes(presets, "library")` checks and the `@debt`-marked `library` checks with trait reads.
4. Rebuild the init answers on the declarative state.
5. Migrate `engrenage.config.ts` and add the changeset.

## Tests

- `library` resolves to `published`; a project without it gets no dist mode and no tests dist tsconfig.
- `preset: "library"` with `traits: { disable: ["published"] }` gets no dist mode.
- A host preset declaring `tests/` as owned keeps the tests environment default out of it.
- Prettier plugins declared in `prettier.config.ts` apply when formatting, without being read by `engrenage sync`'s configuration.

## Done when

The configuration has the decided shape, no module reads a preset name, and the project's checks pass.
