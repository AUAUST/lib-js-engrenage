# #154 architecture: public API of the domains and the formatting contract

- State: OPEN
- Labels: 🚀 — Feature

## Body

Part of #137, under #161. Read the plan, its **`src/` of engrenage** (visibility, placement), **Roles** (`public`) and **Tests (libraries)** sections, before starting.

## Context

- Public entries are discovered from the tsconfig `paths`, which `src.exports` maps by hand; visibility is not declared anywhere else.
- Other AUAUST libraries need engrenage's capabilities: toolkit must write syntactically valid files and delegate formatting to the project's formatter, and read engrenage's understanding of a project.
- Formatting is wired by hand: `foundation/filesystem` receives a Prettier-backed formatter from `project/config`, and the agents domain formats edited files by spawning a process.

Decided:

- Visibility comes from the structure description (`domains.<path>.public`, #148): everything is internal unless declared public. A public domain's specifier is its `specifier` metadata when declared (#148), otherwise its path without namespaces (`tools/tsdown` → `./tsdown`, `tools/agents/claude` → `./agents/claude`, `project/config` → `./config`). `src.exports` keeps only exports that are not domain entries (`./constants`, `./*/constants`). Two public domains with the same specifier fail.
- Public: every `tools` domain (with `agents/claude` and `agents/codex`), `project/config` (`loadConfig(root)` for project sections), `project/package` (the `package.json` model), `project/baseline`, `project/formatting`. Internal: `foundation`, `workflows`, the rest of `project`, including the tsconfig model, `project/structure` (whose resolved structure reaches consumers through `loadConfig`) and the virtual files of `foundation/filesystem`. An internal domain gets no package export and no tsconfig `paths` entry, so its specifier resolves in neither mode; nothing is declared to make a domain internal.
- A public role is importable module by module inside the project; it becomes a package export only when its domain is public and its index re-exports it.
- **Formatting contract**: `project/formatting/ports/Formatter.ts` declares the port; `tools/prettier/adapters/` implements it; `workflows` injects the adapter wherever formatting happens (staged filesystem, agents' edited files). `project/formatting` exposes `formatContent(content, { path, root })` returning the formatted string and `formatFile(path, { root })` built on it.
- Whatever becomes public is tested through its public specifier: its `x.test.src.ts` tests become `x.test.ts`.

## Prerequisites

- #153 is closed.

## Steps

1. Derive the public entries (tsconfig `paths`, package exports, entry discovery) from the declared visibility and specifiers, with the collision check, and drop the domain entries from engrenage's `src.exports`; run `pnpm build:tsdown` and commit the regenerated `package.json`.
2. Add the formatting port, the Prettier adapter and their injection by `workflows`; replace the spawned formatting of the agents domain; expose `formatContent` and `formatFile`.
3. Expose `loadConfig(root)`, the `package.json` model and the baseline through their domains' `index.ts`.
4. Turn the tests these public entries now cover into `x.test.ts`.

## Tests

- `formatContent` formats a TypeScript string with the project's Prettier options; `formatFile` rewrites a file in place.
- An internal domain gets no export; a public one gets its default specifier, or its declared `specifier`.
- `@auaust/engrenage/project/structure` resolves in neither source nor dist mode.

## Done when

The package's exports follow the declared visibility, the formatting contract is the only path to the formatter, and the project's checks pass.
