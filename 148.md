# #148 config: project structure description

- State: CLOSED
- Labels: 🚀 — Feature

## Body

Part of #137, step 2. Read the plan, its **Core model**, **Environments** and **Strictness and the structure report** sections, and #142, before starting.

## Context

Engrenage declares environments (`dirs`, `generated` and `discovered` globs) and discovers public entries from the tsconfig `paths`, but knows nothing about how code is organized inside them. Paths and matchers are scattered (ESLint conventions, a `data/apis/**` ignore in `eslint.config.ts`, hand-listed test setup files). The project structure description gives every directory of every code environment a classification (namespace, domain, role, unclassified) with its source, so the structure report (#156), generated aliases, entry discovery (#154), boundaries (#150) and agent guidance (#151) all read one model.

It lives in `src/project/structure/`, beside the roles of #142, on the current config schemas.

Decided:

- Each code environment's configuration carries its description:
  - `namespaces`: by path, each with optional `layers` (lowest first, `*` for every child not listed), an optional alias `prefix` (consumed by the alias generation) and optional `roles: { enable }`, enabling scoped roles for its subtree (#142);
  - `domains`: metadata by path: `public` (visibility, default `false`), `specifier` (its public specifier, overriding the default derived in #154) and `purpose` (one line);
  - `optOut`: directories excluded from role detection;
  - `strictness`: `"strict"` (default) or `"loose"`.
- The environment root is a namespace for layers and also holds the environment's global roles.
- Classification, highest priority first: configuration, preset defaults, inference. Inference: a directory with `index.ts` is a domain; a known role name (directory or file role of the effective set, #142) is a role unless opted out or a child of a namespace; a non-role directory without `index.ts` holding only domains and namespaces is a namespace; anything else is unclassified. Layers are never inferred.
- Under `loose`, unclassified directories count as plain domains.
- Only declared environment directories are walked; empty directories are ignored.
- With the role system off (`roles: false`), directories are classified as namespaces and domains only.

## Prerequisites

- #142 is closed.

## Steps

1. Add the description options to the environment schemas, typed paths included.
2. In `src/project/structure/`, implement the resolution: walk each code environment's directories, classify each with its source (`config`, `preset`, `inferred`), attach layers, visibility and purpose, and expose the result through the domain's `index.ts` as one tree per environment.
3. Expose the resolved structure on the resolved config, so later consumers read it instead of walking the filesystem again.

## Tests

- A fixture with a namespace ordered by `layers` with `*`, a domain with a sub-domain and roles, a role-named domain opted out, and an unknown directory: each classified with the expected source, the unknown one unclassified under `strict` and a domain under `loose`.

## Done when

The resolved structure of every code environment is available from the config with each directory's classification and source, and the project's checks pass.
