# #159 sync: aliases generated from the project structure description

- State: OPEN
- Labels: 🚀 — Feature

## Body

#137 › #140 · §Library versus app: `#data` only in apps

## Context

`package.json#imports` holds 22 hand-maintained `#<area>/*` entries; every directory move edits them by hand, and apps get no bundler aliases. Decided: `engrenage sync` generates them from the structure description into one flat `#` namespace across Node imports and bundler aliases, and fails on any collision, naming both sources; relative imports stay avoided.

## Steps

1. Declare with the declaration helper (`src/foundation/options/`):
   - top-level `aliases: false | { generated?: boolean, define?: Record<string, string> }`: `false` turns all aliasing off; `generated: false` with `define` replaces the generated global set; `define` alone adds to it;
   - `src.aliases`, same shape, for the `src` set only;
   - `src.bundled: boolean`, default `false`: the `src` code only runs through a bundler.
2. In `src/project/structure/`, derive the alias set from the resolved structure and the options:
   - root aliases for code environments, from each directory's actual name: `#src`, `#tests`, `#scripts`, `#bin`, `#tooling`; `#data` in apps by default, never in libraries; none for an environment at the project root (`tooling`'s `.`) or an output directory;
   - `src` aliases per flat entry of `src/`: a directory gets `#<name>/*`, plus `#<name>` when it has an `index.ts`; a file gets `#<name>`, without extension; a namespace with a `prefix` adds `#<prefix><domain>/*` per domain it holds (empty prefix: `#<domain>/*`), parent aliases staying valid;
   - targets keep today's form, `"#<name>/*": "./src/<name>/*.ts"`;
   - bundler-form keys (`define` entries not starting with `#`) fail unless `src.bundled`.
3. Make the `src` tsconfig producer read `src.bundled`: bundled sets `module: "ESNext"` and `moduleResolution: "Bundler"` explicitly; others switch to a resolution `node` supports without options.
4. Add a sync target writing `package.json#imports`, fully managed while aliasing is on, and for bundled projects the `src` set into the root tsconfig `paths`, which every environment tsconfig inherits, beside the entries other targets own there; `tsconfig.tests.dist.json` keeps `paths: {}`; `--check` reports drift.
5. Declare `#package.json` through `aliases.define`, run `pnpm engrenage sync` and commit the regenerated `package.json#imports`; no import in the repository changes.

## Tests

- A library fixture: root and `src` aliases generated, no `#data`; a `src/tests/` entry colliding with `#tests` fails sync.
- An app fixture with `src.bundled: true` and a `$shopify/*` alias: written to tsconfig `paths`, `#data` present; the same alias with `src.bundled: false` fails.
