# #159 sync: aliases generated from the project structure description

- State: OPEN
- Labels: 🚀 — Feature

## Body

Part of #137, under #140. Read the plan, its **Aliases**, **Library versus app** and **Core model** sections, and #148, before starting.

## Context

`package.json#imports` lists 22 hand-maintained `#<area>/*` subpath imports (`"#config/*": "./src/config/*.ts"`, `"#prettier": "./src/prettier/index.ts"`, …). Every directory move means editing them by hand, and apps that need bundler aliases have no support. The structure description (#148) knows every environment, namespace and flat `src` entry, so `engrenage sync` can generate the aliases and fail on collisions. The relocation of `src/` into namespaces (#139) relies on this.

Decided:

- One flat `#` namespace across Node imports and bundler aliases; `engrenage sync` fails on any collision, naming both sources.
- Root aliases, for code environments only, from each environment directory's actual name: `#src`, `#tests`, `#scripts`, `#bin`, `#tooling`; `#data` in apps, on by default, never in libraries. An environment directory that is the project root itself (the default `tooling` directory `.`) gets none; output directories never get one.
- `src` aliases: each flat entry of `src/` gets `#<name>`: a directory gets `#<name>/*` and, when it has an `index.ts`, `#<name>`; a file gets `#<name>` without extension. A namespace with an alias `prefix` (#148) also generates one alias per domain it holds, `#<prefix><domain>/*` (an empty prefix gives `#<domain>/*`), parent aliases staying valid.
- Targets keep today's form: `"#<name>/*": "./src/<name>/*.ts"`.
- Options:
  - top level `aliases: false | { generated?: boolean, define?: Record<string, string> }`: `false` turns all aliasing off; `generated: false` with `define` replaces the generated global set; `define` alone adds to it;
  - `src.aliases`, same shape, for the `src` set only (`false` turns only it off);
  - `src.bundled: boolean` (default `false`): the `src` code only runs through a bundler. It also sets the `src` tsconfig's bundler module resolution (`module: "ESNext"`, `moduleResolution: "Bundler"`) explicitly, instead of inheriting it from the shared base tsconfig; non-bundled projects switch to a safer default (resolution that `node` supports without options).
- Root aliases are Node subpath imports in `package.json#imports`. The `src` set is Node imports too, unless `src.bundled` is `true`: then it is written once into the root tsconfig `paths`, which every environment tsconfig inherits and Vite, Vitest and tsdown read. Bundler-form keys (`define` entries not starting with `#`) fail unless `src.bundled` is `true`.
- Dist-mode tests resolve no bundler alias: `tsconfig.tests.dist.json` keeps `paths: {}`.
- Library versus app reads the `library` preset until the `published` trait exists; mark that check with a `@debt` marker naming the trait.
- Engrenage declares `#package.json` through `aliases.define`.

## Steps

1. Declare the `aliases`, `src.aliases` and `src.bundled` options with the declaration helper of #146.
2. In `src/project/structure/`, derive the alias set from the resolved structure and the options, with the collision check.
3. Make the `src` tsconfig producer read `src.bundled`.
4. Add a sync target writing `package.json#imports` (fully managed while aliasing is on) and, for bundled projects, the alias entries of the root tsconfig `paths`, beside the entries other targets own there; `--check` reports drift.
5. Run `pnpm engrenage sync` and commit the regenerated `package.json#imports`; no import in the repository changes.

## Tests

- A library fixture: root and `src` aliases generated, no `#data`; a `src/tests/` entry colliding with `#tests` fails sync.
- An app fixture with `src.bundled: true` and a `$shopify/*` alias: written to tsconfig `paths`, `#data` present; the same alias with `src.bundled: false` fails.

## Done when

`engrenage sync` generates every alias of this repository and fails on collisions, and the project's checks pass.
