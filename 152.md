# #152 agents: rewrite the project structure instructions

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, step 10. Read the plan, all of its design sections, before starting.

## Context

The "Project map", "Modules and exports" and "Implementation" sections of `AGENTS.md` describe the structure as it was before the plan (`src/support/<domain>/`, "code that maps to a tool lives in that tool's entry", `tests/helpers/`, a claim that ESLint enforces pure schemas). With the description generating lint (#150) and a project map (#151), the written instructions only need short axioms over the model, plus what neither carries.

Decided:

- The written structure rules become axioms over the settled model: environments and their import directions, namespaces and layers, domains and visibility, roles and their contracts, contract domains with ports and adapters, the config declaration and definers, test variants, generated code and scripts.
- Nothing that lint enforces or the generated project map states is repeated, per the instruction-maintenance rules.
- Where the model matches a known pattern (ports and adapters, layered architecture), the instructions name it instead of explaining it.

## Prerequisites

- #149 is closed.

## Steps

1. Draft the new structure rules of `AGENTS.md` and the axiom pointing to the generated project map.
2. With the maintainer, decide which rules are project-agnostic and belong in shared fragments under `data/agents/`.
3. Apply the approved wording and run `pnpm engrenage sync agents`.

## Consent

Every step edits agent instructions, which `AGENTS.md` ("Instruction maintenance") allows only with the user's explicit consent. Present the final wording and apply it only after approval.

## Done when

`AGENTS.md` and the shared fragments state only the settled structure, nothing already enforced by lint or carried by the project map, and `pnpm engrenage sync --check` passes.
