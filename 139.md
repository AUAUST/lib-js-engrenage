# #139 architecture: src relocated into namespaces and domains

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, step 4. Read the plan, its **Core model**, **`src/` of engrenage** and **Tests layout** sections, before starting.

## Context

`src/` has 17 flat root entries: tool domains, a `config` hub that is both registry and tool, and `src/support/` (`commander`, `debt`, `filesystem`, `json`, `packageJson`, `scaffold`). `config` and `typescript` import each other, `config` imports most tools, and concerns serving several tools have no owner (tsconfig model, baseline, package layout, presets, subprocesses, data files). This task moves every module to its destination domain inside the four namespaces of the plan, so later tasks write code in its final place.

`src/project/structure/` (#142, #148, #162, #164) and `src/foundation/options/` (#146) already sit in their final domains.

The behavior and the public specifiers (`@auaust/engrenage/<name>`) stay identical: the env-agnostic tests of #155 prove it. The `config` hub's internals (`createResolvedConfig`) are redesigned later by the layered registry (#143); here they only move. Every import that still goes from a lower layer to a higher one after the move (mostly `project/config` into `tools/*`) gets a `@debt` marker naming the layered registry.

2. Give every new domain its `index.ts`; namespaces get none.
3. Declare engrenage's structure in `engrenage.config.ts`: the `src` root's layers `["foundation", "project", "tools", "workflows"]`, an empty alias prefix on the four namespaces, `public: true` on every `tools` domain (glob `tools/*`), `tools/agents/claude`, `tools/agents/codex`, and `project/{config,package,baseline}`. A glob in `domains` only adds metadata (plan, **Telling roles apart**); exact paths are needed only for role-named directories outside a namespace.
4. Update `src.exports` so every public specifier keeps its current target module, with one mapping per public specifier instead of today's `./*` and `./*/constants` wildcards, so no internal domain (`project/structure`, `foundation/*`, `workflows/*`) resolves through a public specifier in source mode, and run `pnpm engrenage sync` to regenerate aliases and tsconfig `paths`; then `pnpm build:tsdown` and commit the regenerated `package.json`.
5. Move the tests under one root key per tested environment, mirroring the new layout (`tests/src/<namespace>/<domain>/…`, `tests/bin/engrenage/…`, `tests/scripts/…`), and declare `tests.layout: "mirror"` (#164).
6. Add `engrenage structure --check` to the `ci:check` script.
