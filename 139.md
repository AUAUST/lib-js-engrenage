# #139 architecture: src relocated into namespaces and domains

- State: OPEN
- Labels: 🚀 — Improvement

## Body

#137 · §`src/` of engrenage: namespaces, layers, visibility · §Inside a domain

## Context

`src/` has 17 flat entries, a `config` hub that is both registry and tool, and `src/support/`; `config` and `typescript` import each other. Decided: every module moves to its domain, behavior and public specifiers unchanged, proven by #155's tests; `createResolvedConfig` only moves (#143 redesigns it), and each import still reaching a higher layer gets a `@debt` marker naming the layered registry. `src/project/structure/` and `src/foundation/options/` are already in place.

## Steps

1. Move each module family to its destination; report a module that fits none rather than guessing.

   | Today | Destination |
   | --- | --- |
   | `support/filesystem`, `utils/filesIn`, `config/utils/createFilesystem` | `foundation/filesystem`; `createFilesystem` receives the formatter as a parameter instead of loading Prettier |
   | the direct `spawnSync` sites (`pnpm`, `agents`, `typescript`, `changesets`, `support/commander/resolveBinary`) | a spawn wrapper in `foundation/processes`; pnpm-specific calls stay in `tools/pnpm` |
   | the `createRequire(…).resolve("@auaust/engrenage/…")` sites (`agents`, `github`, `typescript`) | one data-access module in `foundation/data`, resolving through the package's public specifier |
   | `support/json` | `foundation/json` |
   | `utils/syncBlocks`, `utils/syncFiles`, `utils/syncIgnoreFile` | `foundation/blocks` |

   | environment schemas, `createCodeEnvironment`, `resolveCodeEnvironment` | `project/environments` |

   | `support/packageJson`, `config/setup/syncPackageJson`, `config/setup/createPackageStep`, `typescript/utils/resolveExportPaths` | `project/package` |

   | the sync target collection of `bin/engrenage/sync.ts` | `workflows/sync` |

2. Give every new domain its `index.ts`; namespaces get none.
3. Declare engrenage's structure in `engrenage.config.ts`: the `src` root's layers `["foundation", "project", "tools", "workflows"]`, an empty alias `prefix` on the four namespaces (short aliases: `#tsdown/…`, `#config/…`), and `public: true` per §`src/` of engrenage, through the glob `tools/*` and exact paths for the others, except `project/formatting`, which #153 creates and declares.
4. Replace the `./*` and `./*/constants` wildcards of `src.exports` with one mapping per public specifier, each keeping its current target, so no internal domain resolves through a public specifier in source mode; run `pnpm engrenage sync`, then `pnpm build:tsdown`, and commit the regenerated `package.json`.
5. Move the tests under one root key per tested environment, mirroring the new layout (`tests/src/<namespace>/<domain>/…`, `tests/bin/engrenage/…`, `tests/scripts/…`), and declare `tests.layout: "mirror"` (#164).
6. Add `engrenage structure --check` to the `ci:check` script.
