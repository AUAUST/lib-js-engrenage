# #141 architecture: modules sorted into roles

- State: OPEN
- Labels: 🚀 — Improvement

## Body

#137 · §Inside a domain: roles and their imports · §Decisions: one verb per module kind

## Context

After #139, `utils/` mixes pure helpers with resolvers, producers, readers, writers and definers; `setup/` holds eleven `produceTsconfig*` producers; names differ only by word order (`resolveNodeRuntime`, `resolveRuntimeNode`; `resolveCodeEnvironment`, `createCodeEnvironment`; a private `readLibrary` in both the editions and API generators). Decided: each module moves to the role its content has; definers (`define…Config`, `create…Config`) go to `operations/`.

## Steps

1. In every domain, move each module of `utils/`, `setup/` and `config/` to its role per §Inside a domain. A module stays in `utils/` only if its imports fit the `utils/` row, so #150 finds nothing to fix there; anything needing more, such as a runtime import of another domain, usually goes to `operations/`. No `internals/`, `helpers/`, `classes/` or `data/` role: an error class goes to `errors/`, a stateful service to `operations/`, a value object beside the types or utils it serves.
2. Rename the modules whose names permute another's words or do not state their result, by §Decisions' verbs.
3. In `engrenage.config.ts`, define the ESLint conventions as a discovered, semi-structured role, `conventions/<category>/<rule>.ts` with a default export and required categories, and drop the `src.discovered` glob it replaces.
4. Move `tests/helpers/` to the tests `utils/` role (`#tests/utils/…`) and update its imports; #152 rewrites the instructions naming `tests/helpers/`.
