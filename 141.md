# #141 architecture: modules sorted into roles

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, step 5. Read the plan, its **Inside a domain** and **Roles** sections, before starting.

## Context

After the relocation (#139), modules sit in their final domains but still in today's directories: `utils/` mixes pure helpers with resolvers that read files, producers, readers, writers and definers; `setup/` holds the eleven `produceTsconfig*` producers beside init steps and sync targets; names compensate with word permutations (`resolveNodeRuntime` versus `resolveRuntimeNode`; `resolveSourceRuntime`, `resolveCodeEnvironment` versus `createCodeEnvironment`; a private `readLibrary` in both editions and API generators). This task sorts every module into the role its content has and gives each kind one verb, so lint can later enforce the role contracts.

Decided:

| Role | Holds |
| --- | --- |
| `utils/` | pure, contained functions only |
| `operations/` | impure logic: resolvers that read files or the environment, producers, readers, writers, loaders, and definers (`define…Config`, `create…Config`) |
| `setup/` | init steps (`create…Step`) and sync targets (`sync…`) only |
| `config/` | the pure declaration of the domain's options |
| `plugins/` | the tool's own plugins, one per module |
| `types/`, `constants.ts` | unchanged |
| `errors/` | error classes |

- A module stays in `utils/` only if its imports fit the plan's `utils/` row (§4): `utils/`, `types/` and `constants.ts` here and above, global roles, and other domains' `index.ts` type-only as their layer allows. A module needing anything else, such as a runtime import of another domain, goes to the role its content has, usually `operations/`, so #150's `utils/` rule finds nothing to fix.
- One verb per kind: `create…Step` for init steps, `sync…` only for sync targets, `generate…` for generators, `define…Config` for definers. A name states the module's distinct result; no two modules differ only by word order.
- The ESLint conventions are a discovered, semi-structured role: `conventions/<category>/<rule>.ts`, default export, categories required. Define it in `engrenage.config.ts` and drop the `src.discovered` glob it replaces.
- Shared test helpers move from `tests/helpers/` to the tests environment's `utils/` role (`#tests/utils/…`). The instructions mentioning `tests/helpers/` are rewritten by #152; leave them.

## Prerequisites

- #139 is closed.

## Steps

1. In every domain, move each module of `utils/`, `setup/` and `config/` to the role its content has, per the table above.
2. Rename the modules whose names are word permutations of another or do not state their result, following the verbs above.
3. Add the `conventions` role definition and drop the replaced `discovered` glob.
4. Move `tests/helpers/` to `tests/utils/` and update its imports.
