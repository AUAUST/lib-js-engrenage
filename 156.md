# #156 cli: report of the resolved project structure

- State: OPEN
- Labels: 🚀 — Feature

## Body

#137 · §Model: classification and strictness

## Context

A misclassified directory silently skews aliases, lint scope, boundaries and agent guidance, and nothing shows how engrenage reads a codebase. Decided: `engrenage structure` (`bin/engrenage/structure.ts`) only parses input and prints; rendering lives in `src/project/structure/`, reusing the resolved structure, never a second walk.

## Steps

1. In `src/project/structure/`, render one line per directory, grouped by environment: its classification (namespace with its layers, domain with its visibility, role, tests mirror with the path it mirrors (#164), unclassified with its reason) and its source (`config`, `preset`, `inferred`), plus every file of a domain that fits no role, reported as unclassified, since it reveals a missing role or domain.
2. Add the command and its `--check` mode, which exits non-zero on an unclassified directory of a `strict` environment only.

## Tests

- A fixture with an unknown directory in a `strict` environment: reported as unclassified, `--check` fails; the same fixture as `loose`: reported, `--check` passes.
- Namespaces print their layers and every line its source.
- A `mirror` tests environment with a directory lacking its counterpart: printed with its reason, `--check` fails.
