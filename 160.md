## Context

Engrenage is also the JavaScript part of projects it does not own: a Shopify theme (Liquid at the root, output into a shared `assets/`), a Laravel or Kirby project (PHP `tests/` and `config/`, a plugin in a subdirectory). Yet `eslint.config.ts` needs a hand-written `ignores: ["data/apis/**"]`, the build empties its whole output directory (`build.emptyOutDir`, tsdown's `clean`), and git and GitHub assume the project root is the repository root. Decided: default-deny, engrenage lints, formats, scans and writes only the declared environment directories and its own files, and edits shared files (`package.json`, ignore files, `.vscode/settings.json`, `AGENTS.md`) only through managed keys or marker blocks.

## Steps

1. Derive the scopes from the declared environments, never `**`: ESLint `files` from the code environments (`src`, `bin`, `scripts`, `tests`, `tooling`; `data` is not code), replacing the `**/*.{ts,tsx}` default of `typescript.files` wherever it serves as a scope (`createRecommendedRules`, `createImportPresets`, `resolveScope`); the `prettier:all` paths and the ESLint and `.prettierignore` ignore blocks from every declared environment. `.gitignore` keeps its blocks unchanged. Drop the `data/apis/**` ignore from `eslint.config.ts`.
2. Replace `build.emptyOutDir` (`buildSchema`) with `build.clean`: `"all"` (default) empties the output directory, `"emitted"` removes only the files the previous build emitted, recorded in a manifest in the cache directory (`cacheFor`), written only after a successful build, with no manifest removing nothing; `false` removes nothing; `"emitted"` suits an output directory shared with a host, `"all"` an owned one; implement `"emitted"` with one manifest module in `project/build`, used by a tsdown and a Vite plugin.
3. Make the `tooling` defaults cover the root config files (`files` globs, matched at the project root only) and `tooling/` (`dirs` default `[".", "tooling"]`), whose code files are all included and walked like `src`, so `ResolvedTooling` separates root files from walked directories, and the only home of project tool configuration code (never `scripts/`, `src/` or a root `config/`), set by the defaults, not linted; no file of this repository moves; the project root itself stays unwalked by `resolveEnvironmentStructure`, so `.` contributes files only. Remove the `@debt` marker about the unwalked project root.
4. Resolve the repository root in `tools/git`: the nearest ancestor of the project root holding `.git` (file or directory), else the project root. Write the GitHub workflows through a filesystem rooted there, with the project's path as their `working-directory` when it differs; GitHub workflows keep their names (`ci.yml`, `publish.yml`), which repository automation depends on.

## Tests

- A fixture with an undeclared directory holding an invalid TypeScript file: neither linted nor formatted.
- `"emitted"`: a host file in the output directory survives a rebuild; a file emitted by the previous build and no longer produced is removed.
- A `tooling/` directory holding a tool domain resolves into the `tooling` structure tree; a directory at the project root outside every environment is not walked.
- A project in a subdirectory of a repository: the GitHub workflows land under the repository root.

## Done when

No engrenage scope reaches outside the declared environments and its own files.
