# #160 config: engrenage touches only declared environments

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, under #144. Read the plan, its **Mixed codebases** and **Environments** sections, before starting.

## Context

Engrenage is also the JavaScript part of projects it does not own entirely: a Shopify theme (Liquid directories at the root, output into a shared `assets/`), a Laravel or Kirby project (PHP `tests/` and `config/`, a plugin living in a subdirectory of the repository). Today several scopes are not derived from the declared environments: ESLint needs a hand-written `ignores: ["data/apis/**"]` in this repository's `eslint.config.ts` because it lints files no environment declares; the build empties its whole output directory (`build.emptyOutDir`, tsdown's `clean`); the git and GitHub domains assume the project root is the repository root.

Decided:

- Default-deny: engrenage lints, formats, scans and writes only the declared environment directories and its own files. Every derived scope (ESLint `files`, Prettier globs, ignore blocks) comes from the declared environments, never `**`.
- The `build` contract's clean policy replaces the boolean: `"all"` empties the output directory, `"emitted"` removes only the files the previous build emitted (recorded in a manifest in the cache directory), `false` removes nothing. Default `"all"`.
- Git and GitHub domains resolve the repository root separately from the project root.
- GitHub workflows keep their names (`ci.yml`, `publish.yml`): every library's repository automation depends on them.
- The `tooling` environment covers the root config files (its `files` globs at the project root) and the `tooling/` directory, walked like `src` (same roles, no layers, one domain per tool). The project root itself is never walked by the structure resolution (`src/project/structure/utils/resolveEnvironmentStructure.ts`), so `.` contributes files only.
- Shared files (`package.json`, ignore files, `.vscode/settings.json`, `AGENTS.md`) stay edited only through managed keys or marker blocks.

## Steps

1. Derive the ESLint `files`, the Prettier globs and the ignore blocks from the declared environments; drop the `data/apis/**` ignore from `eslint.config.ts`.
2. Replace `build.emptyOutDir` with the clean policy and implement `"emitted"` in the tsdown and Vite adapters.
3. Make the `tooling` defaults cover the root config files and `tooling/`, resolve `tooling/` into a structure tree, and remove the `@debt` marker about the unwalked project root.
4. Resolve the repository root in `tools/git` and use it in `tools/git` and `tools/github`.

## Tests

- `"emitted"`: a host file in the output directory survives a rebuild; a file emitted by the previous build and no longer produced is removed.
- A `tooling/` directory holding a tool domain resolves into the `tooling` structure tree; a directory at the project root outside every environment is not walked.
- A project in a subdirectory of a repository: the GitHub workflows land under the repository root.
