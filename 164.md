# #164 structure: tests layout following the tested environments

- State: OPEN
- Labels: 🚀 — Feature

## Body

#137 › #140 · §Model: strictness

## Context

`resolveEnvironmentStructure` (`src/project/structure/utils/`) leaves every non-role `tests` directory unclassified (26 today: `tests/bin/engrenage`, …), so `engrenage structure --check` (#156) never passes on a `strict` tests environment. Decided: `tests.layout: "roots" | "mirror"`, default `"roots"`; engrenage declares `"mirror"` in #139; `project/structure` owns the classification, #156 prints it.

## Steps

1. Declare `layout` on the tests environment with the declaration helper (`src/foundation/options/`).
2. In `resolveEnvironmentStructure`, classify the tests environment after the other code environments, adding the `mirror` kind, its mirrored environment and path, and the unclassified reason to the structure types:

   | Directory                                                                                        | `roots`             | `mirror`                                                                                                              |
   | ------------------------------------------------------------------------------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------------- |
   | Child of the tests root named after a code environment other than `tests`, `data`: a root key | `mirror` of it      | `mirror` of it                                                                                                        |
   | Tests role directory (`fixtures/`, `utils/`), at any depth                                       | role, unchecked     | role, unchecked                                                                                                       |
   | Below a root key                                                                                 | `mirror`, unchecked | `mirror` when the mirrored environment's resolved structure has the same path (`tests/src/tools/tsdown` → `src/tools/tsdown`), else unclassified: missing counterpart |
   | Any other child of the tests root                                                                | unclassified: unknown root key | same                                                                                                  |

   `mirror` checks assignability only: a mirror may stop at any depth and hold the tests of everything below, any directory may hold test files, a namespace's mirror included, file names need no counterpart. File roles (`setup.ts`) stay as they are.
3. Make `loose` count unclassified tests directories as `mirror` instead of domains.

## Tests

- `mirror`: `tests/src/a/x.test.ts` passes where `src/a/b/` exists; `tests/src/a/c/` fails where `src/a/c/` does not; `tests/fixtures/any/` passes; `tests/hello/` fails.
- `roots`: `tests/src/anything/deep/` passes; `tests/hello/` fails.
