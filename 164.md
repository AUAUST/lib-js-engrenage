# #164 structure: tests layout following the tested environments

- State: OPEN
- Labels: 🚀 — Feature

## Body

Part of #137, under #140. Read the plan, its **Environments** (**Tests layout**) and **Strictness and the structure report** sections, and #148, before starting.

## Context

`resolveEnvironmentStructure` (`src/project/structure/utils/`) classifies a directory as a namespace, domain, role or unclassified. Test directories hold test files and no `index.ts`, so every non-role directory of `tests` is unclassified: 26 on this repository today (`tests/bin/engrenage`, `tests/project/structure`, …). `engrenage structure --check` (#156) could never pass on a `strict` tests environment, and #139 adds it to CI. Tests need their own classification, following the environments they test.

Decided (plan, **Tests layout**):

- The `tests` environment takes `layout: "roots" | "mirror"`, default `"roots"`. Engrenage declares `"mirror"` for itself in #139, once its tests are moved.
- In both layouts, the children of the tests root are root keys or tests roles. A root key is named after a code environment other than `tests` and `data` (`src`, `bin`, `scripts`, `tooling`), whatever its directories, and is classified `mirror` of that environment. Tests role directories (`fixtures/`, `utils/`) are roles at the root and at any depth, their content unchecked; file roles (`setup.ts`) stay as they are.
- `roots`: every directory below a root key is `mirror`, unchecked.
- `mirror`: a directory below a root key is `mirror` when the mirrored environment's resolved structure has a directory at the same path (`tests/src/tools/tsdown` → `src/tools/tsdown`). Only assignability is checked: a mirror may stop at any depth and hold the test files of everything below (`tests/src/foo/wholeSuite.test.ts`), any directory may hold test files, a namespace's mirror included, and file names need no counterpart. A directory with no counterpart is unclassified.
- A `mirror` node records the environment and path it mirrors; an unclassified tests directory records why (an unknown root key, a missing counterpart), which the report prints.
- `strict` fails `--check` on unclassified tests directories; under `loose`, they count as `mirror` instead of domains.
- `project/structure` owns the classification; `engrenage structure` (#156) prints it and owns `--check`.

## Steps

1. Declare `layout` on the tests environment with the declaration helper of #146.
2. In `resolveEnvironmentStructure`, classify the tests environment by its layout after the other code environments resolve, adding the `mirror` kind, the mirrored environment and path, and the unclassified reason to the structure types.
3. Make `loose` count unclassified tests directories as `mirror`.

## Tests

- `mirror`: `tests/src/a/x.test.ts` passes where `src/a/b/` exists; `tests/src/a/c/` fails where `src/a/c/` does not; `tests/fixtures/any/` passes; `tests/hello/` fails.
- `roots`: `tests/src/anything/deep/` passes; `tests/hello/` fails.

## Done when

The tests environment classifies every directory under both layouts, its unclassified directories carry a reason, and the project's checks pass.
