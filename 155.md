# #155 vitest: dist mode tests the built package through public specifiers

- State: CLOSED
- Labels: 🐛 — Bug: Critical

## Body

Part of #137, under #158. Read the plan, its **Tests (libraries)** and **Library versus app** sections, before starting.

## Context

Dist mode (`vitest:dist`, run by `pnpm build`) exists to run the test suite against the built package, as a consumer would get it. It does not: tests import internals through `#…` subpath imports, which resolve to `src/` in both modes, so dist mode tests the sources again. A library's suite must reach the package only through its public specifiers (`@auaust/engrenage/…`): source mode maps them to `src/`, dist mode resolves them through `exports` to the build output. Tests that need internals are explicitly source-only and never run in dist mode, so no test silently falls back to `src/`.

Current state:

- `src/vitest/config/createVitestConfig.ts`: source mode uses `tsconfig.json` (`paths` mirror `src.exports`) with `resolve.tsconfigPaths: true`, and `createOutDirGuard` (`src/vitest/plugins/`) fails on resolutions into the build output. Dist mode (`buildMode`) uses `tsconfig.tests.dist.json` (`paths: {}`) with `resolve.tsconfigPaths: false`. Nothing fails on resolutions into `src/` in dist mode.
- The tests environment's `files` option defaults to `defaultTestsFiles` (`**/*.{test,spec}.{ts,tsx}`, `src/config/constants.ts`), resolved in `createResolvedConfig` (`tests.files`) and read by ESLint through the `files.test` scope (`src/eslint/utils/resolveScope.ts`, used by `noMisplacedTests` and several conventions).
- 78 test files, all `*.test.ts`; 45 already import `@auaust/engrenage`. Tests under `tests/bin/engrenage/` spawn `node bin/engrenage/index.ts`.

Decided:

- Test variants, side by side in the same directory:

  | File | Runs in | Imports |
  | --- | --- | --- |
  | `x.test.ts` | source and dist | public specifiers and `#tests/…` only |
  | `x.test.src.ts` | source mode only | internals through `#…`; never the package name |
  | `x.test.dist.ts` | dist mode only | public specifiers only; may reach dist-only artefacts |

- Test files are matched from three parts of the tests environment, each configurable: a location glob (default `**/*`), a suffix glob (default `.{spec,test}`) and an extension glob (default `.{ts,tsx}`). Engrenage combines them into the plain pattern and the two variant patterns (location + suffix + `.src` or `.dist` + extension). They replace the single `files` glob. Vitest's default include ignores the variants (checked on 5.0.5); the variant must follow the suffix.
- Dist mode fails on any resolution into `src/` through a plugin, and resolves no tsconfig `paths` or bundler alias.
- The executable is spawned per mode: `bin/engrenage/index.ts` in source mode, the built file from `package.json#bin` in dist mode.
- Variants, the dist guard and the import rules apply to libraries only. The `published` trait that will carry this does not exist yet, so this task reads the `library` preset and marks the check with a `@debt` marker naming the `published` trait.
- The import rules are an ESLint convention in `src/eslint/conventions/structure/` until boundaries are generated from the structure description (#150).
- Keep today's test paths; they move with their sources later.

Done in `de78623` (steps 1–4 and 6 of the original plan): the location, suffix and extension parts, the variant includes, the dist plugin `createSourceGuard`, the conventions `noInternalImportsInPublicTests` and `noPackageImportsInSourceTests`, and the test rewrite. Every test under `tests/bin/engrenage/` became `x.test.src.ts`: they import `bin` modules or spawn `bin/engrenage/index.ts`, so dist mode never runs the built executable (`package.json#bin`, `./dist/bin/engrenage.mjs`). `x.test.src.ts` may keep importing `bin` modules (plan, **Tests (libraries)**).

## Steps

1. Add a helper under `tests/helpers/` returning the executable for the current mode: `bin/engrenage/index.ts` in source mode, the file of `package.json#bin` in dist mode.
2. Add an `x.test.ts` under `tests/bin/engrenage/` that spawns the executable through the helper and checks a command's observable result, so dist mode exercises the built executable; move every remaining spawn of `bin/engrenage/index.ts` to the helper.

## Tests

- Dist mode spawns the built executable; source mode spawns its source entry.

## Done when

`pnpm build` runs at least one test spawning the built executable, `pnpm test` runs it against the source entry, and the project's checks pass.
