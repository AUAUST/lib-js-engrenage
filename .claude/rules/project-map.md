## Notation

Trees: `name*` public domain, `{…}` sub-domains, `#alias/…` import alias, `[isolated]` peers never import each other, `[domains]` every child directory is a domain, `[collects: …]` entry re-exporting those roles from every domain, `[public: …]` roles public in that domain's subtree, `[debt: …]` why that member does not fit the project's Compass, beside its purpose.

| Relation | A domain may import |
| --- | --- |
| `own-roles` | its own roles and files, excluding its index and entry |
| `global-roles` | the global roles of the top-level namespace root |
| `ancestor-roles` | the roles of its ancestor domains, as a sub-domain |
| `sub-domain` | the target's `index.ts` and public roles, through its nearest sub-domain's surface |
| `lower-layer` | the target's `index.ts` and public roles, through a domain in a lower layer |
| `peer` | the target's `index.ts` and public roles, through a peer domain (same layer, unless isolated) |
| `root-entry` | any public surface, from the top-level namespace root file |

## Roles

Effect levels, purest first: `pure` < `confined` < `observing` < `effectful`. A role's level caps both what its modules do while they evaluate and what their exports do once invoked, unless it states its `evaluation` and `invocation` ceilings apart. A role with an invocation ceiling imports at runtime only roles whose invocation ceiling is that level or a purer one. Global roles import each other, and domains only with `import type`. Other domains import a role's modules one by one only when it is `public`, otherwise only through its domain's index. They import a `collected` role's modules inside sub-domains too, past their parent domains' surfaces, and a `modules` role's directly; no index lists them.

- `pure`: Compute from arguments only, without observable changes.
- `confined`: Mutate caller-owned values or maintain a private memo cache.
- `observing`: Read the context or write diagnostics without changing state later operations read.
- `effectful`: Change state later operations can read, including staged writes and spawned processes.
