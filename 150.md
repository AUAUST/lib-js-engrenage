## Body

## Context

No rule enforces the structure: `eslint.config.ts` and the ESLint entry configure no boundary rule; the only structural conventions are `noMisplacedTests`, `noDefaultExport` (`src/eslint/conventions/imports/`, "no default export except discovered files") and #155's interim test-import conventions `noInternalImportsInPublicTests` and `noPackageImportsInSourceTests` (`src/eslint/conventions/structure/`). The resolved structure (#148, the resolved config's `structure`) knows every environment, namespace, layer, domain, visibility and role, so the rules are generated from it rather than written by hand, for engrenage and for every consumer.

#138 ran a generator on today's `src/` before any relocation: 454 `surfaces`, 186 `utils`, 79 `domain-content`, 32 `types`, 11 `environments` and 3 `global-roles` errors, most of them root causes that #139, #141, #143 and #154 remove.

Decided:

- The engine is eslint-plugin-boundaries (7.x), as validated by #138; rules the plugin cannot express are engrenage conventions over the resolved structure.
- One rule per row of the plan's **Lint** table, exposed through engrenage's own ESLint plugin and named like its other rules, each built on `boundaries.rules.dependencies` with its own `default` and messages; all of them share one set of `boundaries/*` settings. A single `dependencies` rule cannot combine rows, since its last matching policy wins.
- Elements: one exact descriptor (`partialMatch: false`) per classified directory of the resolved structure, deepest first, enumerated when the ESLint config loads. The `relationship` and `parent` selectors and captures are therefore unavailable; the generator enumerates the paths each policy needs instead. A directory added while ESLint runs is unknown until the config reloads.
- Every environment file belongs to an element or to a `boundaries/files` category: root config files of `tooling` and the test variants (`test`, `test-src`, `test-dist`, built from the tests environment's location, suffix and extension parts) included. Library test rows match `dependency.source` against the package name and its subpaths, since source mode resolves the package name into `src/`, with `checkAllOrigins: true`.
- `boundaries/root-path` is the project root (the plugin defaults to the process working directory), and `boundaries/legacy-templates` is `false`. Messages are written per policy with `{{to.file.path}}`, and state what is violated and how to fix it.
- The import contract comes from the import rules resolved in `project/structure` (#162), never derived again here: each resolved rule becomes policies of its row, type-only rules matching `dependency.kind: "type"`, and its reason the message. Rules #162 flags as not enforceable by import analysis are skipped.
- Role contracts (#142) are enforced for built-in and project roles alike: match, accepted files, nesting, structure, export style, `index`, discovery; `constants.ts` exports deeply read-only values (type-aware); `index.ts` declares no local value except a SCREAMING_CASE metadata constant; `types/` declares no runtime value. `public` is part of the sub-domain row. Domain content is a convention looking up the linted file in the resolved structure; `boundaries/no-unknown-files` is not used, since its message cannot say how to fix the file.
- Runtime references to `data/` and `bin` being spawned only are not enforced; only their import half is.
- Library-only rows read the `published` trait (#153).
- With the role system off (`roles: false`), no role or boundary rule is generated.
- Consumers extend the description, from which every rule derives; a `boundaries` option of `defineEslintConfig`, keyed by row, appends policies after that row's generated ones, as the escape hatch.
- No cycle rule.
- Existing violations are fixed in the code before the rules land; suppressions only on explicit request.

## Steps

1. In `tools/eslint`, generate the `boundaries/*` settings (elements, file categories, root path) from the resolved structure, the tests environment's `mirror` directories included (#164), and one rule per import row of the **Lint** table from #162's resolved rules.
2. Add the role-contract and domain-content conventions, and remove `noDefaultExport`, `noInternalImportsInPublicTests` and `noPackageImportsInSourceTests`, which they replace.
3. Add the `boundaries` option to `defineEslintConfig`.
4. Fix the violations the rules report in this repository.

## Tests

- A fixture with two namespaces under layers: an import into a higher layer fails, into a lower layer or a peer's `index.ts` passes, into a peer's private `utils/` module fails, into a peer's `adapters/` module passes, a sub-domain's import of its parent's `utils/` passes, and a `utils/` module's type-only import of a peer's `index.ts` passes while its runtime import fails.
- A role directory holding an `index.ts` its contract forbids fails; a `utils/` module with two exports fails.

## Done when
