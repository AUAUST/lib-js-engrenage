# #150 eslint: boundaries and role contracts generated from the project structure

- State: OPEN
- Labels: 🚀 — Feature

## Body

#137 › #149 · §Imports · §Inside a domain · §Library versus app · #138: findings and generated settings per row

## Context

No rule enforces the structure: the only structural conventions are `noMisplacedTests`, `noDefaultExport` and #155's interim `noInternalImportsInPublicTests` and `noPackageImportsInSourceTests` (`eslint/conventions/structure/`). Run on today's `src/`, #138's generator reported 454 `surfaces`, 186 `utils`, 79 `domain-content`, 32 `types`, 11 `environments` and 3 `global-roles` errors, mostly root causes #139, #141, #143 and #154 remove. Decided: eslint-plugin-boundaries 7.x, with the settings #138 validated (adjustments 1–6); rules it cannot express are engrenage conventions over the resolved structure.

## Steps

1. In `tools/eslint`, generate the `boundaries/*` settings from the resolved structure, the tests `mirror` directories included (#164):
   - one exact descriptor (`partialMatch: false`) per classified directory, deepest first, enumerated when the ESLint config loads, so a directory added while ESLint runs is unknown until it reloads; the generator enumerates paths instead of `relationship`, `parent` and captures;
   - every environment file in an element or a `boundaries/files` category, root config files of `tooling` and the test variants included;
   - `boundaries/root-path` the project root, `boundaries/legacy-templates: false`.
2. Add one rule per import row of §Imports, named like engrenage's other rules and built on `boundaries.rules.dependencies` with its own `default`. Each of #162's resolved rules becomes policies of its row: type-only rules match `dependency.kind: "type"`, library test rows match `dependency.source` against the package name and its subpaths with `checkAllOrigins: true`, and the reason becomes a message (with `{{to.file.path}}`) stating the violation and its fix. Skip rules #162 flags as not enforceable; add no cycle rule.
3. Add conventions over the resolved structure for every role contract field of built-in and project roles (`public` excepted, covered by the sub-domains row), for `constants.ts` exporting deeply read-only values (type-aware), `index.ts` declaring no local value but a SCREAMING_CASE metadata constant, `types/` declaring no runtime value, and domain content; not `boundaries/no-unknown-files`, whose message cannot say how to fix the file. Remove `noDefaultExport`, `noInternalImportsInPublicTests` and `noPackageImportsInSourceTests`.
4. Add a `boundaries` option to `defineEslintConfig`, keyed by row, appending policies after that row's generated ones: an escape hatch, since consumers extend the description every rule derives from.
5. Fix every violation the rules report in this repository before they land; suppressions only on explicit request.

## Tests

- A fixture with two namespaces under layers: an import into a higher layer fails, into a lower layer or a peer's `index.ts` passes, into a peer's private `utils/` module fails, into a peer's `adapters/` module passes, a sub-domain's import of its parent's `utils/` passes, and a `utils/` module's type-only import of a peer's `index.ts` passes while its runtime import fails.
- A role directory holding an `index.ts` its contract forbids fails; a `utils/` module with two exports fails.
