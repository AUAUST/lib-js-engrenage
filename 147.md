# #147 codegen: generators in scripts, generated code placed by role

- State: OPEN
- Labels: 🚀 — Improvement

## Body

#137 › #144 · §Environments: `scripts` · §Decisions: one verb per module kind

## Context

Generators live in `src/` beside the code they produce, and generated code sits in a `generated/` directory or among handwritten modules. Decided: generators of engrenage's own sources live in `scripts/` with their hand-maintained inputs, never imported by `src/`; generated code is placed by domain and role, each file wholly generated or wholly handwritten; `syncBarrels` stays a public capability of `tools/typescript`, only its runner is a script.

| Generator (after #141)                     | Run by                                  | Writes                                                       |
| ------------------------------------------ | --------------------------------------- | ------------------------------------------------------------ |
| `syncEditions` (`tools/typescript`)        | `scripts/support/codegen/editions.ts`   | `project/baseline/editions/constants.ts` (placed by #139)    |
| `syncApiDeclarations` (`tools/typescript`) | `scripts/support/codegen/apis.ts`       | `data/apis/*.d.ts`                                           |
| `syncRuleTypes` (`tools/eslint`)           | `scripts/support/codegen/rules.ts`      | `tools/eslint/types/Rules.ts`, `tools/eslint/types/rules/**` |
| `syncConfigTypes` (`project/config`)       | `scripts/support/codegen/config.ts`     | one `Config.ts` for the whole configuration                  |
| `syncBarrels` (`tools/typescript`, public) | `scripts/support/codegen/barrels.ts`    | `// @barrel` blocks in handwritten barrels                   |

Names may differ slightly after #139 and #141; locate them by name.

## Steps

1. Move `scripts/support/` to `scripts/codegen/` (one `generate…` module per generator) and `scripts/pnpm.ts`, with the command entry at `scripts/index.ts`; point the `support` package script at it, so `pnpm support codegen …` keeps working.
2. Move `syncEditions`, `syncApiDeclarations`, `syncRuleTypes` and `syncConfigTypes` into their scripts, and `esMemberCompatKeys` and `esInterfaceAliases` (`tools/typescript/constants.ts`) into `scripts/codegen/constants.ts`.
3. Make the config generator write each domain's input type into that domain's `types/`, and the composed `Config` type into `workflows/registry/types/`.
4. Update the environments' `generated` globs, which exclude generated files from formatting and lint, and run every generator with `--check`.

## Tests

The existing generator tests pass from their new location; `pnpm support codegen --check` reports no drift.

## Done when

`src/` holds no generator and no `generated/` directory.
