# #147 codegen: generators in scripts, generated code placed by role

- State: OPEN
- Labels: 🚀 — Improvement

## Body

Part of #137, under #144. Read the plan, its **`bin`, `scripts`, `tests`, `data` of engrenage** and **Roles** sections, before starting.

## Context

Generators live in `src/` beside the code they produce, and generated code sits in a `generated/` directory or mixed with handwritten modules:

| Generator (after #141) | Run by | Writes |
| --- | --- | --- |
| `syncEditions` (`tools/typescript`) | `scripts/support/codegen/editions.ts` | `project/baseline/editions/constants.ts` (`export const editions = { … }`), placed by #139 |
| `syncApiDeclarations` (`tools/typescript`) | `scripts/support/codegen/apis.ts` | `data/apis/*.d.ts` |
| `syncRuleTypes` (`tools/eslint`) | `scripts/support/codegen/rules.ts` | `tools/eslint/types/Rules.ts`, `tools/eslint/types/rules/**` |
| `syncConfigTypes` (`project/config`) | `scripts/support/codegen/config.ts` | one `Config.ts` for the whole configuration |
| `syncBarrels` (`tools/typescript`, public) | `scripts/support/codegen/barrels.ts` | `// @barrel` blocks in handwritten barrels |

Hand-maintained generator inputs (`esMemberCompatKeys`, `esInterfaceAliases`) sit in `tools/typescript/constants.ts`. The module and file names may differ slightly after #139 and #141; locate them by name.

Decided:

- Generators of engrenage's own sources live in `scripts/`, never in `src/`; `src/` never imports `scripts/`. Their hand-maintained inputs sit beside them.
- Generated code is placed by domain and role like handwritten code; no `generated/` directory. A file is wholly generated or wholly handwritten.
- `syncBarrels` is a public capability for consumers and stays in `tools/typescript`; only its runner is a script.
- Generated files are recognized by the environments' `generated` globs, which exclude them from formatting and lint.
- Generators use the verb `generate`.

## Prerequisites

- #143 is closed.

## Steps

1. Move `scripts/support/` to `scripts/codegen/` (one module per generator, `generate…`) and `scripts/pnpm.ts`, with the command entry at `scripts/index.ts`; point the `support` package script at it, so `pnpm support codegen …` keeps working.
2. Move `syncEditions`, `syncApiDeclarations`, `syncRuleTypes` and `syncConfigTypes` into their scripts, and `esMemberCompatKeys` and `esInterfaceAliases` into `scripts/codegen/constants.ts`.
3. Make the config generator write each domain's input type into that domain's `types/`, and the composed `Config` type into `workflows/registry/types/`.
4. Update the `generated` globs and run every generator with `--check`.

## Tests

The existing generator tests pass from their new location; `pnpm support codegen --check` reports no drift.

## Done when

`src/` holds no generator and no `generated/` directory, each generated file sits in its domain and role, and the project's checks pass.
